# Local taste analysis

Flutter stores local save, remove, and open events in an indexed SQLite table, separate from saved works and the portable library backup. Existing saved works are seeded once on first initialization. Turning analysis off pauses new event recording; re-enabling it does not reconstruct missed events. Reset deletes the events but retains the initialization marker, so previously saved works are not automatically analyzed again. It does not remove saved works or analysis preferences.

Current saved evidence is reconstructed from save and remove events. Distinct open and organic save evidence also adjusts tag weights using the native lift formula once the source has at least 30 observed works and 10 organic active saves. Open events are deduplicated by item for this calculation, not by native discovery session. Weekly and monthly summaries count unique saved and opened works from timestamped events, including works unsaved later; they use Monday-start calendar weeks and calendar months in the device time zone. Search context, search sessions, reading time, metadata updates, and the native report cache are not implemented. Newly imported works are non-organic evidence and do not count as historical saves. Evidence is not synchronized through iCloud or Drive. These differences matter when comparing native reports and recommendations, and no identical ranking is claimed.
