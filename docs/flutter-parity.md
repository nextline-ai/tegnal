# Flutter parity contract

This is an implementation checklist derived from the working native Apple source on 2026-10-26, including the user's uncommitted native changes. It is not a claim that the Flutter port implements these features. At the start of this audit, `flutter/lib/main.dart` was the Flutter counter template. See [flutter-roadmap.md](flutter-roadmap.md) for the implemented modules, focused checks, final Android build, and remaining acceptance work.

The portable backup codec is now implemented in `flutter/lib/data/backup_codec.dart` with seven focused fixture tests in `flutter/test/core/backup_codec_test.dart`. This verifies the codec in isolation, not the remaining application feature matrix. The tests cover native-shaped envelopes, legacy formats, source remapping, secret exclusion, date units, validation before mutation, and transaction rollback.

Legacy import services are implemented in `flutter/lib/data/legacy_import.dart` and seven synthetic tests in `flutter/test/core/legacy_import_test.dart`. They cover read-only user/catalog SQLite, match-only/full catalog staging, metadata conversion, cancellation/rollback, and Anime Boxes default import behavior. Codec export now retains more than 100 search-history records, covered by one additional focused regression. Basic import screens are connected. Advanced destination choices, progress/cancel UI and on-device validation remain separate checklist items. See `flutter/README.md` for current limits.

Android is the first release target; Windows and Linux are subsequent targets of the same application and domain model. Preserve the native application's recognizable screen hierarchy, artwork-led layouts, interactions, localized copy, and independent Comics/Image libraries. Platform capabilities must be reported honestly. Android AI may use only system services already installed and available on the device: no external model downloads, bundled replacement models, or silent cloud inference.

All source paths below are relative to the repository root. The existing Apple application remains the behavioral reference and must not be modified as part of the port.

## Reader interaction contract

1. **Page indexing and progress:** native persisted `reader_page_<galleryID>` is one-based; internal pages are zero-based. Clamp to actual page count. An explicit page above 1 overrides stored progress, then align to the start of a 1–4-page spread. Persist only in contexts that permit progress recording; preserve the separate resume flag.
2. **Layout modes:** horizontal paging, vertical paging, continuous scroll; spreads of 1–4 pages in comics. RTL reverses relevant page/swipe/arrow behavior. Last incomplete spreads do not wrap or index beyond the manifest.
3. **Tap zones:** normalized horizontal `0.3…0.7` toggles the quick menu; outer zones turn pages when side navigation is enabled. Long press toggles saved/bookmarked status and reports the actual result. Double tap/pinch zoom; dragging while zoomed pans the image and locks parent page scrolling as necessary.
4. **Exit/preview gestures:** swipe down at original zoom closes paged reading. In continuous mode, only the top handle/safe zone starts dismissal; page dragging continues scrolling. A bottom upward swipe opens page previews (image mode opens details). Gestures are disabled appropriately during translation, sheets, jumps, and active zoom.
5. **Quick menu and auxiliary surfaces:** retain page-number jump, bookmark, exit, translate, details, preview, download access and reader settings. Jump validates user input. Details show categorized metadata/tag chips that can search after dismissing the reader. Preview selection jumps to the intended page. Loading/error states always provide an exit.
6. **Preferences:** independent Comics/Image values; default horizontal mode, LTR, one page, auto-advance off, ten-second interval, keep-awake on, prefetch three, dimming zero, side taps on. Auto interval is 2–120 seconds; comics prefetch choices are 0/2/3/5; dimming clamps to 0–0.65. Honor menu placement, optional page number and mode-specific settings.
7. **Lifecycle:** auto advance pauses for menus, settings, translation, zoom, jump and inactive application, and stops at the last page. Prefetch cancels when inactive or obsolete. Restore the previous wake-lock state on exit. Native page prefetch is memory-only; durable downloads are a separate user action.
8. **Keyboard/accessibility:** Escape exits the foremost active reader layer; arrows navigate respecting RTL; `m` quick menu, `f` saved toggle, `i` details (`ReaderShortcuts.swift`). Ignore reading shortcuts while a field/modal owns input. Expose named next/previous/menu/bookmark actions, current page, loading/failure, focus order, and adequate touch targets. Desktop shortcuts must not depend on touch gestures.

## Portable data and compatibility

### Backup envelopes

| Shape | Native version / limit | Required handling |
| --- | --- | --- |
| Combined library | `format: "tegnal-library"`, `version: 1`, maximum 128 MiB | Preserve `exportedAt` ISO-8601 string and nested `comics`, `images`, `challenges`. Native combined decoder currently requires these three objects. Export all three even for an empty library. |
| Comics standalone | No `format` field; `version: 1` or `2` | Snake-case `exported_at`, folders/works/artists, optional history/saved_searches. Export current version 2. Work membership is folder names, not device-local numeric IDs. Normalize a unique legacy `*_group_id` field to `source_group_id`. |
| Image standalone | `format: "tegnal-image-library"`, `version: 1`, standalone maximum 64 MiB | Keep servers, folder IDs/colors, favorite post payloads/membership/save dates, history, savedTags, blacklist and selectedServerIDs. Accept historical `number-memo-image-library` only when importing, then normalize. |
| Challenge standalone | `format: "tegnal-challenges"`, `schemaVersion: 1`, maximum 10 MiB; at most 200 unique games | Validate every definition. Accept historical `number-memo-challenges` for import only. Export definitions; sessions are separate local data. |

Native JSON has mixed time representations: combined `exportedAt` and comics date strings use ISO-8601; uncustomized Codable `Date` fields such as image backup `exportedAt` encode seconds since 2001-01-01 UTC; history/save numerical timestamps use their explicitly specified Unix seconds. Do not globally apply milliseconds-since-epoch conversion. Read actual nested model keys and numeric types from `BooruModels.swift` and `ChallengeModels.swift`; preserve null-vs-missing defaults where decoders distinguish them. ARGB values may exceed signed 32-bit range. IDs must retain 64-bit integer precision.

### Merge rules and exclusions

- Validate all envelopes, uniqueness, positive IDs, folder references, allowed kinds, finite timestamps, colors, server URLs and media URLs before writing. Reject unsupported versions and over-limit input with a useful message. Validate encoded output as well.
- Comics folders merge by name; works merge by gallery ID, with supplied non-null metadata updating existing records and unspecified fields retained. Folder associations are unioned; imported order precedes local remaining order. Artists merge by `(name, kind)` and search times keep the newest value.
- Image servers match canonical origin, and imported server IDs must be remapped to existing IDs. Handle ID collision with a different origin without overwriting the existing server. Remap favorites, history, saved tags, blacklist and selected IDs consistently. Folder order/color/membership follows the imported payload while absent local records survive.
- Importing an older standalone comics/image/challenge backup must not clear the other libraries. Repeated import creates no duplicates. Cancellation and a rejected nested payload leave recoverable local state intact.
- Design the Flutter restore with one real atomic transaction where possible. Native nests writes to two separate database writers; do not treat that structure as proof of distributed atomic commit. If using separate Flutter stores, stage/validate and implement recovery so a failed second commit cannot leave a silent partial restore.
- Portable backup intentionally excludes media files, downloads, thumbnails/caches, cookies, credentials, and device preferences. Combined image capture uses `post.cloudMetadata`; preserve that redaction/normalization. It does not include the separate full Taste event history or local challenge sessions. Do not label a JSON metadata export as an offline-media archive or full session migration.
- Raw SQLite import is a separate compatibility surface from the portable JSON codec. Native GRDB migration history and archived Vision fingerprints are not a portable Flutter storage format.

### Future synchronization semantics

`LibrarySyncRecord.swift` uses logical table keys, timestamped changes and tombstones; a timestamp tie is broken by device string. Some values use Swift synthesized associated-enum Codable encoding and `Data` base64, so they are not interchangeable with plain JSON scalar rows. Port the wire format deliberately if reusing those documents.

Native library files reside under `Documents/LibrarySync/v1`; Taste files use `Documents/TasteSync/v1`, independently versioned controls/events/reports and reset epochs. Preserve account changes, deletion history, source identity, control-first reconciliation and reset revocation in any future provider. Windows iCloud file visibility alone does not implement app-entitled discovery, identity or safe reconciliation. File backup compatibility can ship independently of live sync.

## Platform capability boundaries

| Native dependency | Android-first behavior | Windows/Linux behavior |
| --- | --- | --- |
| SwiftUI/UIKit, Liquid Glass, SF Symbols | Shared Flutter layout and equivalent icons/semantics; adapt back navigation, safe areas and text scaling. | Same domain/screens with pointer/keyboard/focus, resizing, file dialogs and desktop scroll behavior. |
| Vision OCR / VisionKit Live Text / Apple Translation | Query installed, authorized system service and language availability; unavailable is a normal state. Never call model-download or install APIs to satisfy a translation request. | Use only an explicitly implemented available system facility; otherwise report unavailable while preserving manual copy/search/navigation paths that exist. |
| Vision feature prints | Recompute only with an actually available system facility; never import Apple archived feature observations. | Same capability boundary; keep algorithm/revision-specific caches isolated. |
| Statistical Smart analysis | Port pure statistics/ranking and localized templates. No language model is required. | Same implementation and deterministic fixture results. |
| iCloud Drive APIs / Apple entitlements | No automatic iCloud parity. Use portable import/export until a real provider is integrated. | Same; no simulated sync status. |
| WKWebView session transport / account storage | Implement Android browser and secure account adapters, isolate cookies by required server context, and prove the request path. | Choose and validate a browser adapter per target; do not assume mobile web-view support extends to both desktops. |
| Apple share extension / security-scoped URLs / Photos | Android share intents and document selection; appropriate save/share destination, cancellation and read grants. | Native file/open/save/share workflows where available; handle read-only and denied files. |

This document makes no claim that a particular Android AI SDK, hardware model or service is universally available. Availability must come from a real native capability adapter at runtime. A hard-coded `true`, a successful channel call that does no work, or a model that must first be downloaded does not satisfy the constraint.

## Delivery phases and completion gates

1. **P0 — Portable foundation and faithful shell.** Launch on Android, Windows and Linux from the same project; implement independent persisted libraries/preferences, retained mode/tab navigation, adaptive artwork components, folder CRUD, saved-work entry and compatible metadata backup. Gate: restart retains data; source fixtures import and re-export without semantic loss; an invalid nested backup changes neither library; empty installations have no demo/preset records presented as user data.
2. **P1 — Browsing and reading.** Implement real source/transport adapters, website connection, engine-specific image feeds, both comics backends, gallery/post details, full reader contract, queue/download persistence and offline opening. Gate: complete a save → organize → read → resume → download → offline-read → unsave workflow with fixtures and explicitly selected live verification where authorized. Exercise error, cancellation, stale source and multi-server identity cases.
3. **P2 — Complete core workflows.** Finish artists/search/tag/history/blacklists/pools, importers, metadata queue, deterministic Smart/reports/controls, Challenges, localization and settings. Gate: no visible action is a no-op; source-scoped statistics and challenge timer/session fixtures agree with native behavior; native import/export fixtures remain compatible. Imports and long-running work expose progress/cancel and useful failures.
4. **P3 — Platform integrations and release readiness.** Implement installed-system-only translation/OCR/similarity where genuinely available, embedded-browser accounts, Android share intake, desktop file/media/window behavior, and any separately chosen sync provider. Gate: both available and unavailable capability paths work without external model downloads; platform-specific omissions remain explicitly documented. A release claiming complete parity must either implement each matrix row or name and justify every remaining platform limitation.

Verification must follow `AGENTS.md` and `docs/testing.md`: inspect the diff, run only affected methods/classes or a proportionate build, and stop once the relevant check passes. UI automation, full suites, additional devices and live integration checks require their requested scope. For the original audit, source inspection and link/path validation were sufficient. Subsequent codec/importer work used only the focused fixture checks described above; no native application suites, UI automation, live websites or device matrix were run.

## UX alignment pass — 2026-10-27

This pass compares the native presentation code and Korean marketing screenshots,
not just the presence of feature names. The Flutter app keeps Material UI 1.8.0
controls and bundled Pretendard. Native Apple sources are unchanged.

| Everyday flow | Flutter change |
| --- | --- |
| Switch Comics / Images | Share the selected destination as native does; retain both modes' nested navigation trees and scroll state. Capture each screen's mode so hidden trees cannot change the other library's settings. |
| Open an image | Open the full-screen reader directly from Saved, Explore, and Pools. Next/previous uses the caller's filtered, ordered loaded collection; controls and Android Back dismiss in order. |
| Open a comic | Present the gallery/details as a modal, with page previews that open the selected reader page. The normal Read action resumes progress. Saved title/note editing and confirmed removal remain contextual actions. |
| Saved / Artists | Add work numbers/links into a chosen folder, including local metadata placeholders; artist/group rows open matching saved works, with remote search kept as a separate action. Collection menus provide top/bottom/month jumps. |
| Search | Start the initial feed when Explore becomes active. Suggestions fill the current token without submitting. Empty-field focus opens history with saved-search stars, removal and confirmed clearing. Search controls return when scrolling upward. |
| Image sources / sort | Saved and Explore share a real server picker; the Saved toolbar no longer disguises a layout toggle as the server control. An explicit empty server selection stays empty. Offer only the intersection of supported native sort modes, preserve typed query constraints, and restore the previous feed/order on a typed server rejection. |
| Pools | Enter through More, choose a source when needed, then navigate pool list → pool feed → viewer. Back returns to the preserved list. |
| Reader | Add actionable details/tags, thumbnail previews, numeric page jump, default-visible persisted image notes, and pause automatic advance while controls are open. Capture download identity before asynchronous enqueue. |
| Setup / import | Connect Website → Import Data → mode-switch preview; allow setup later, replay and import-only entry. The tutorial preview does not change the real mode. A dismissible import reminder persists locally. |
| Visual layout | Center the root mode control, use the image-mode More icon, tighten the floating navigation, and restore the darker grouped surfaces and blue accent visible in the references. |

Focused checks cover the changed navigation, library, search, setup, reader and
sort behaviors. The optional isolated capture harness uses only an in-memory
library and local artwork; it must not seed the installed app. Android runtime
checks use the existing emulator and compare the library before/after.

This is not complete native feature parity. Remaining contracts above still
include reader spreads and advanced gesture/preferences, viewer pagination beyond
the currently loaded collection, artwork column/spacing preferences, API-level
connection validation/cookie management, metadata backfill, advanced Smart and
Challenge workflows, and native system-service integrations. Live source/account
behavior, OAuth, and Windows/Linux execution require their own focused validation.
